# Migrating from 0.1.0a1 to 0.2.0a1

The new model is opt-in for existing manifests. Keep the original file and
artifacts before migrating; results depend on the chosen model.

```json
{
  "schema_version": "1.1",
  "observation_model": "exact-local-sequence-presence-v2"
}
```

Add these fields to the complete manifest; this fragment is not a runnable input.
An omitted model continues to mean `original-sites-presence-v1`, including in old
schema 1.0 inputs. New `demo` and `init` templates explicitly select v2.

The legacy model does not rematch primers and can depend on edit representation.
V2 reconstructs final DNA and matches all exact local heteroprimer products in
both orientations. This resolves representation dependence, but does not add
mismatch tolerance or empirical PCR calibration. Use `compare-models` to inspect
model-sensitive witness changes.

Alternative IDs or edit notations yielding the identical final local diploid
sequence state are no longer counted as genomic counterexamples. Results expose
that classification. V2 reports may contain multiple products per allele/assay:
read `signal_ids` and `products`; a null singleton `signal_id` is not sufficient
to infer no signal.

`init` now requires `--full-insert` or `--read-bases N`. Do not choose the former
merely to get a command to pass. It is a measurement assumption.

Old full analysis/scan JSON can be integrity-verified with `verify`. Exact replay
requires the originating package version: a 0.1.0a1 result is replayed with
0.1.0a1, not the changed schema in 0.2.0a1. A committed fixture generated by the
original executable tests this distinction. Neither checksum nor replay proves
that the scientific model describes a real experiment.
