# DotMatch 0.6.0

DotMatch 0.6.0 brings the first CRISPR counting run, local count comparison, and
assignment review into the released package.

## Check the package before using study data

Run the packaged synthetic example from an installed copy:

```bash
python3 -m pip install dotmatch==0.6.0
dotmatch --version
dotmatch demo --out-dir first-run/
```

The command uses nine bundled synthetic reads and makes no network requests. It
checks native per-guide counts and all four read outcomes against committed
expectations, then writes an offline review bundle. The fixture tests software
behavior; it is not a biological study or an accuracy benchmark.

## Prepare CRISPR inputs

`dotmatch crispr quickstart` validates every FASTQ pattern before creating a
project. It copies reads by default. Use `--link-reads` when the original reads
will remain available and unchanged. New projects stay in draft until settings
are reviewed and explicitly marked ready.

## Compare raw count tables

`dotmatch compare-counts` compares raw count matrices by guide and sample
identifiers. It reports exact integer differences, excluded axes and input
hashes without normalization or biological interpretation. Existing output
paths are refused.

## Assignment review and workflow hardening

The assignment-sensitivity review adds full-library search, policy comparison,
guide and read-transition inspection, identity-checked local read decisions,
and scoped TSV/SVG exports. The release also includes strict FASTQ, target-table,
threshold, and count validation; sparse AnnData adapters; and the
`python -m dotmatch` CLI entry point.

The matching kernel, default counting policies, historical benchmark outputs,
and published biological scope are unchanged. See the
[Changelog](../../CHANGELOG.md) for the complete list.

PyPI and GHCR artifacts are produced and checked by the release workflow.
Bioconda, BioContainers, and a version-specific Zenodo DOI require separate
upstream verification; the source tag alone does not establish their
availability.
