# DotMatch 0.6.4

DotMatch 0.6.4 is a backward-compatible patch release for two first-run
CRISPR-screen failures. Matching and counting semantics are unchanged.

## Linked-read projects pass preflight

`dotmatch crispr quickstart --link-reads` creates symlinks inside the project
so large FASTQ files do not need to be copied. DotMatch 0.6.3 created those
projects but `dotmatch assay check` then refused its own symlinks after resolving
them outside the project directory. The containment check now accepts a
lexically in-project symlink while continuing to reject `..` path escapes.

## Correlation gates apply to declared replicates

The CRISPR reliability gate no longer treats every sample pair as biological
replicates. Plasmid, T0, and selected samples are expected to diverge, so their
pairwise correlations remain reported but do not fail the run merely for being
below `min_pairwise_sample_pearson`.

Samples can declare an optional `condition` in `[[samples]]`. Only samples that
share a condition are held to the pairwise-correlation threshold. A low
correlation within a declared condition still fails the configured reliability
gate.

These changes correct software validation behavior. They do not establish
biological accuracy, sample identity, or screen quality.

See the [Changelog](../../CHANGELOG.md) for the complete list. PyPI and GHCR
artifacts are produced and checked by the release workflow. Bioconda,
BioContainers, and a version-specific Zenodo DOI require separate upstream
verification.
