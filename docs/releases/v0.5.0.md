# DotMatch 0.5.0

DotMatch 0.5.0 adds a one-pass assignment-policy comparison and makes the first
CRISPR counting workflow easier to inspect and reproduce.

## Assignment-policy sensitivity

`dotmatch sensitivity` compares exact, Hamming radius-one and best-distance
radius-one assignment over the same fixed read windows. It reuses a native
index and one query per distinct window in each bounded batch, while preserving
every read's multiplicity. Outputs include three count tables, per-guide
changes, read-state transitions, sample QC, checksums, a self-contained HTML
report, and an optional changed-read ledger.

The command does not choose a matching policy, estimate biological accuracy,
or change existing counting defaults. Existing output directories are refused;
a completion manifest is written only after a successful, conserved run.

## Package reliability

- Share strict CSV/TSV/gzip target parsing between the Python API and CLI,
  including BOMs and reordered named columns. Reject empty or duplicate IDs;
  retain duplicate sequences with distinct IDs for ambiguity review.
- Defer optional scientific imports until their interfaces are used.
- Stop presenting ambiguous candidate indices as assigned dataframe names.
- Normalize dataframe sequence case and explain missing FASTQ identifiers.
- Preserve original decompressed UTF-8 FASTQ content for explicitly requested
  streaming hashes, before sequence normalization.
- Correct instructions for reviewing and promoting an existing draft assay.
- Parse benchmark counts as integers without floating-point rounding or silent
  omission. Distinguish successful comparison execution from count identity.

## Website and onboarding

A scientist-focused homepage, native-generated examples, CRISPR first-run and
sensitivity guides, and a local browser library-collision checker replace the
agent-first introduction. Task pages have independent canonical URLs and
GitHub Pages exports. Agent tools remain available as an optional automation
route.

## Scope and distribution

This release concerns known-target read assignment and scientific workflow
inspection. It does not add genome alignment, CRISPR off-target cutting
prediction, cell/UMI processing, or gene-level screen statistics. Historical
benchmark artifacts are not rewritten into new performance claims.

PyPI and GHCR publication are verified by the release workflow. Bioconda,
BioContainers and a version-specific Zenodo DOI require separate upstream
verification; a source tag alone does not establish their availability.

Install the published release with `python3 -m pip install dotmatch==0.5.0`.
Check `dotmatch --version`, then inspect `dotmatch sensitivity --help`.
