# DotMatch 0.6.1

DotMatch 0.6.1 is a backward-compatible patch release for evaluating an
existing count workflow and for producing auditable release artifacts.

## Compare workflows with explicit identities

`dotmatch compare-counts` now accepts `--sample-map` and `--guide-map` TSV
files when two workflows use different names for the same samples or guides.
The command validates missing names, duplicates, collisions, and shared
annotations before writing output. Reports preserve the asserted pairs and
mapping-file checksums.

A mapping is an assertion, not biological proof. Verify sample identity from
the sample sheet and guide identity from the original library files before
interpreting differences.

## Correct comparison reporting

The public CRISPR comparison report now separates successful execution from
count identity. Aggregate guide totals are explicitly labelled `identical`,
`different`, `not_comparable`, `inconsistent_summary`, or `unverified`.
Aggregate totals do not establish per-sample agreement or which workflow is
biologically correct.

## Reproducible source distributions

Building the same source and version with the same `SOURCE_DATE_EPOCH` now
produces byte-identical source archives, including isolated PEP 517 builds.
The release gate rebuilds the archive independently and compares its SHA-256.

The installed count-comparison walkthrough also points to the packaged
`dotmatch demo` fixture; the separate `examples/count_comparison/` fixture is
available only from a source checkout.

The matching kernel, assignment policies, benchmark measurements, and
published biological scope are unchanged. See the
[Changelog](../../CHANGELOG.md) for the complete list.

PyPI and GHCR artifacts are produced and checked by the release workflow.
Bioconda, BioContainers, and a version-specific Zenodo DOI require separate
upstream verification; the source tag alone does not establish availability.
