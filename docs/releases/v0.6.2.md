# DotMatch 0.6.2

DotMatch 0.6.2 is a backward-compatible patch release for strict FASTQ input
handling and prospectively recorded independent evaluations.

## Fail closed on malformed FASTQ

The native count-only and full-record readers now enforce the same structural
rules as the strict Python reader. Invalid identifiers, malformed separator
lines, empty or non-printable sequence/quality fields, truncated records, and
corrupt gzip streams stop with record and line context. Outputs opened before a
parse failure are removed rather than left looking complete.

This changes rejection of malformed input, not matching or counting semantics
for valid FASTQ.

## Lock an evaluation before viewing results

The installed CLI now provides:

```bash
dotmatch evaluation-packet template evaluation.protocol.json
dotmatch evaluation-packet lock evaluation.protocol.json evaluation.locked.json
dotmatch evaluation-packet verify evaluation.locked.json
dotmatch evaluation-packet complete \
  evaluation.locked.json evaluation.results.json evaluation.completed.json
```

The lock covers input hashes, tool settings, endpoints, failure criteria, scope
limits, and tied-rank handling. Completion preserves that protocol hash and
requires every endpoint exactly once. A valid packet makes protocol changes
detectable; it does not prove commands ran, biological correctness, independent
authorship, or permission to publish.

## Checked public Yusa evidence

The source distribution includes fail-closed count-table and MAGeCK downstream
comparators plus pinned records for the public ERR376998/ERR376999 Yusa
workflow. DotMatch 0.6.1 and MAGeCK 0.5.9.5 agreed across 87,437 guide rows and
174,874 count cells. Keyed sgRNA fields, non-rank gene statistics, and
FDR<=0.05 hit sets also agreed; ordinal rank differences occurred only inside
exact statistical tie blocks.

These are implementation-reproducibility results for one workflow. They do
not validate the screen's biology, establish general accuracy, or demonstrate
external adoption. The included Yusa request remains an unsent draft owned by
no evaluator.
